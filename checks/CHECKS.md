# Mirror's Edge Catalyst: Archipelago location list

Generated by `build_checks.py` from `ground_truth.json`. The full list, one row per check, is in `locations.csv` / `locations.json`. Columns: id, name, category, district, area, default, flag, hash, detection, note.

**852 locations defined, 792 on by default.**

## How a check is detected

Every location is one progression flag. `hash = djb2a(flag name)` (seed 5381, `h = ((h*33) ^ byte) & 0xFFFFFFFF`). The same hash works in both places:

- **Save file:** the `PROF_SAVE` record key in any `ProgressionManagerData*` section (§12). This is the same method `me_catalyst_hint_bridge.py` already uses for GridLeaks.
- **Live memory:** the node hash in the flag table at `[BASE+0x257C9D8]` (§56). A client can poll node+0x18 while the game runs, without waiting for autosave.

**Verified:**
- The 324 GridLeak hashes match `gridleaks_hashes.json` exactly (324/324).
- Every category resolved against a real save (`decoded_check.json`), and the counts look plausible. For example, 116 electronic parts, 26 recordings, 11/11 side missions and 3 deliveries were collected in that save.
- There are no duplicate hashes, IDs or names.

The collectible totals (324 / 251 / 45 / 42 / 40) match the in-game World Progression screen.

**Mission detection.** Side missions and deliveries use `_CompletedTime`, not the `SilverCompleted_`/`BronzeCompleted_` flag. The design plans to write `SilverCompleted_<m>` to unlock missions for replay (§25), so that flag cannot also be the check. §25 also proved that a real completion overwrites the synthetic `_CompletedTime` seed with a different value. So the check is "`_CompletedTime` is nonzero and differs from what the seed save wrote". **Simpler, per §74:** `SilverCompleted_` alone unlocks the mission (written live, it appears at the next checkpoint restart), so the client never needs to write `_CompletedTime`. The check is then just `_CompletedTime` going 0 → nonzero.

## Deliberately excluded

- `SecurityCameras_*Destroyed` (194): too granular and not a progression item.
- `Doors`, `FastTravel_Discovered*` (6), `LairPhotoLocations_*` (8), `CriticalPathProgression_*` (16).
- `IntelCollectiblesWorld` (35): a codex/counter, not pickups.
- `Collectables_*` totals.
- Dashes / time trials: not save-tracked (§16), and the Beat Revival mod doesn't restore them.

## Known gaps / to verify in-game

1. **Collectible names are placeholder numbers.** "GridLeak - Anchor 017" corresponds to one GUID, but the order is alphabetical by GUID, not by map position. Electronic parts keep their real chip numbers. To make hints useful, a later pass could pull world positions from the level data.
2. **`Ct` in opportunity-mission names** (CtPh6) is assumed to be Rezoning/Construction. This is unverified.
3. **Zone codes** (AcCv = Crystal Valley and so on) come from the zone table used earlier. Worth spot-checking one of each against the map.
4. **Balance.** 792 locations against a ~34–39 ability pool needs a lot of filler (XP bundles? a flag like `XP` exists but granting it is untested) or a smaller default set. A sensible YAML option set: toggles per collectible category plus side missions, opportunities, deliveries, hubs, nodes and billboards.

## Item pool note (conflict to resolve)

§21 says the reachable pool is **34** `Unlocks_*` flags: the set present in both the player's save and the community 100% save.

§57 granted `Unlocks_IncreasedHealth1–4` together (3 and 4 are in the "24 unreachable" group) and the bar went from 4 to 8 segments. That is four flags and four segments, so 3/4 almost certainly count, but they were never tested alone. So the 24 are not simply dead. Some (at least the IncreasedHealth tiers, i.e. the gear upgrades) are real and are just normally earned another way. Each of the 24 needs a live test before it goes into the pool.

**The 34 confirmed:** Coil, CombatRecovery, Disrupter_IncreaseRange, Disruptor_Overload, Disruptor_StunHumans, Disruptor_StunMech, DoubleWallrun, ExtendedComboVulnerability, ExtendedSlide, FastClimb, FlowAttack, FlowAttack_PowerAttack, FlowAttack_Special_PowerAttack, Focus, Focus_FlowAttackFluency, Focus_ReachFlow_Increase, Focus_ReachFlow_IncreaseExtra, Glove, HandToHandCombat, ImpactAttack_PowerAttack, ImpactAttack_Special_PowerAttack, IncreasedHealth0, IncreasedHealth1, IncreasedHealth2, LowerHealthEnforcer, LowerHealthProtector, LowerHealthSentinel, LowerHealthShockProtector, MoveEnemyAttack, MoveEnemyBack (Switch Place), PositionalAdvantage, QuickTurn, Shift, SkillWindowSkillRoll.

The grapple (MAG Rope) is story-gated through `CriticalPathProgression_HasCollectedMagRope*`, not `Unlocks_*`. It can still be an item: Swing was revoked and granted live (§69). Swing, PullUp, PullDown and LineConnector are separate flags, so they could be separate items (progressive grapple).

**Live-grant status:**
- Proven: `+3A75790(entity, v, 0)` works for MoveEnemyBack, IncreasedHealth1, DoubleWallrun and the story-gated MAG Rope Swing (`CriticalPathProgression_HasCollectedMagRopeSwing`, §69), in both directions. It works right after a normal load with no death (§67). The client re-scans for the entity before every grant because respawns rebuild it.
- Abilities with no live entity (Focus family, LowerHealth*, Glove, Disruptor_Overload, ExtendedComboVulnerability, PositionalAdvantage): calling the same function on the flag's **persistent** entity works. Proven for Focus (§72). A table write alone applies at the next death (§71).
- Every other ability is untested live. The save-edit + restart path works for all 34.
